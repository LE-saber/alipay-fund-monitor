# Alipay Fund Monitor

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md)

**[AutoX.js](https://github.com/aiselp/AutoX) による Android のファンド保有状況監視と戦略自動化。**

> **実資金を扱う機能があります：**ライブモードは Alipay でファンドを売買し、実際の支払いを発生させます。専用の 1 元テストも実際の購入です。まず既定の dry-run モードで計画を確認し、その後に実操作を有効にするか判断してください。

個人利用向けのプロジェクトです。Android のユーザー補助機能で保有情報を取得し、カード表示と設定済み戦略の実行を行います。投資助言ではありません。自動操作がプラットフォームの規約と矛盾したり、画面変更によって動かなくなったりする場合があります。MIT ライセンスは資金損失を保証しません。

## 機能

- Alipay のファンド保有画面から名称、保有額、前日・保有損益、収益率を取得し、合計を画面表示と照合。
- 検索・並べ替え、上昇を赤／下落を緑で示すカード、取得・戦略進捗のフローティング表示。
- 実行ごとの履歴（直近 100 回）、注文詳細、現在の操作終了後の一時停止、保存済み進捗からの再開。
- 金額制限、大口確認、ローカル監査記録を伴う売買。支払いパスワードは Android Keystore を使用した AES-GCM で暗号化保存。
- 設定可能な四つの戦略を、売却フェーズの後に購入フェーズという順序で実行。

### 戦略の意味

| テンプレート | 計画時の動作 |
| --- | --- |
| `base` | 保有額が目標未満なら、設定された金額の購入を提案 |
| `dca` | 有効なグループ内の各ファンドに購入を提案し、複数一致なら最高のグループ金額を使用 |
| `costReduce` | 損失時、最初に一致する有効な損失段階、または有効なフォールバックを使用 |
| `takeProfit` | 最も高い一致済み有効利益段階を使い、設定された口数割合で売却 |

購入では `base` と `dca` の金額が競合し、同額なら `base` を優先します。一致した `costReduce` の金額は勝った項目に**加算**して、一つの購入注文にまとめます。すべての戦略から単純に最大金額だけを選ぶわけではありません。

## 実行時の制約

- `dryRun` の既定値は `true` で、パスワード送信前に停止します。ライブ操作には支払いパスワード設定が必要です。
- 金額の型、小数桁、上下限、追加確認のしきい値を検証します。
- 各ファンドの失敗を個別に処理し、失敗と画面復帰を記録します。
- バッチ状態は完了済み・不確定な操作を保存します。中断時に送信中だった操作は要確認とし、再開時にスキップして無条件の再購入を避けます。
- 専用の実テストは要求額を 1 元に固定しますが、購入資格、拒否、最終結果は Alipay に依存します。無リスクなサンドボックスではありません。
- 監査ログ：`/sdcard/Download/alipay_trade.log`。ログ、保有情報、支払い設定は私的データとして扱ってください。

## Android で実行

**AutoX.js v6**、ユーザー補助機能、他のアプリ上への表示権限が必要です。既存の記録は Redmi HyperOS / Android 15 を対象としており、全端末の互換性を示すものではありません。

1. 自分の端末に AutoX.js v6 を入れ、必要な権限を付与します。
2. Auto.js–Autox.js の VSCode 拡張で Wi-Fi 接続し、`main.js` を開いて F5 で実行します。
3. **↻** で取得、**⚙** で設定・戦略確認、**▶** で戦略実行フローを開きます。
4. 画面遷移、取得内容、計画を確認している間は dry-run を維持します。

アプリの UI は中国語のままです。README の翻訳はアプリの動作や UI 言語を変更しません。

## パッケージ化

`project.json` のエントリーは `main.js`、アイコンは `res/logo.png` です。従来の手順はローカルで用意する `release/` を使用しますが、このディレクトリは Git の対象外で、チェックアウトには含まれません。必要なファイルとリソースをローカルで準備して端末へコピーし、AutoX.js のメニューで UI アプリケーションを選択してパッケージ化します。生成した APK は `adb install` でインストールします。端末操作を変更する前に[従来の画面遷移・支払い手順](verified-flows/README.md)を確認してください。

## 開発と構成

| パス | 用途 |
| --- | --- |
| `main.js` | Android UI、情報取得、売買、戦略を含む単体スクリプト |
| `src/` | 抽出されたロジック、設定、診断。同等のロジックは `main.js` にも内包 |
| `test/` | Node による純粋ロジックのテスト |
| `verified-flows/` | 記録済みの画面遷移・支払いスクリプトと説明 |
| `monitor/` | ADB 取得処理と HTML 監視画面 |
| `probe*.js`、`test_pwd_flow.js` | 端末診断。一部は支払い画面へ進むため実行前に確認 |

純粋ロジックの確認コマンド：

```bash
node test/strategy-logic.test.js
node test/trade-logic.test.js
node test/apply-query-sort.test.js
node test/run-history.test.js
```

これらは現在の Alipay UI や実際の約定を検証するものではありません。文書保守では支払いフローを実行しません。
